Privacy, Ethics & AI Governance Policy

Ethical AI Framework & Non-Clinical Boundaries

Official privacy, ethical safeguards, and governance architecture for SIH26186.

CRITICAL ETHICAL DIRECTIVE: The system is a WELFARE SUPPORT and DECISION-SUPPORT platform. It is NOT a medical diagnosis system and must NOT diagnose psychiatric illness. It must NOT be used for promotion, demotion, termination, disciplinary action, performance reviews, or clandestine surveillance.

1. Core Welfare Objective & Participation

The platform exists solely to identify early operational strain signals, provide transparent feature attribution, offer supportive rest and workload recommendations, and facilitate human-in-the-loop review by qualified Welfare Officers. Personnel participation is voluntary and oriented around care coordination.

2. Role-Based Access Control (RBAC) & Data Isolation

Access is enforced via cryptographically signed JWT tokens and backend middleware guards:

  • Personnel: Can access only their own profile, check-in history, ML predictions, and support requests.
  • Welfare Officers: Can view triage alerts, assigned follow-up schedules, and aggregated welfare indices without administrative command over personnel.
  • System Administrators: Manage system health, API bridges, model metrics, and audit logs without viewing private personnel notes.

3. Data Minimization & Security Controls

The platform collects only operational variables relevant to welfare (e.g. duty hours, sleep hours, subjective work pressure). Plaintext passwords are never stored; all credentials use salted bcrypt (10 rounds). All sensitive actions are logged in the immutable audit trail.

4. Synthetic / Demo Dataset Limitation

Because real armed forces welfare records are classified and sensitive, this prototype utilizes a documented synthetic dataset (synthetic_personnel_welfare_dataset.csv) for training the Random Forest classifier. Real-world deployment would require institutional governance, clinical review, and authorized datasets.
